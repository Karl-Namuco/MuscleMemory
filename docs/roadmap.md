# Development roadmap

The current client includes account setup, training configuration, workout logging, interruption recovery, and history across desktop, tablet, and mobile layouts. Phase 4 is in progress: its first increment implements Rolling recommendations and qualifying split advancement. Fixed scheduling, Adaptive scoring, availability, and schedule overrides remain outstanding, so Phase 4 is not complete. Each major phase ends with relevant executed checks and a review before proceeding. The owner reported deploying Phase 2; the agent has not published Phase 3 or the initial Phase 4 increment.

| Phase                      | Scope                                                                                                         | Acceptance gate                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 0 — Planning               | Architecture, data model, scheduling design, scope, risks                                                     | Approved plan                                                                                            |
| 1 — Foundation             | Account access, approval enforcement, onboarding, editable preferences, responsive shell, initial PWA         | A user can register, receive approval, finish onboarding, preserve/edit preferences, and sign out safely |
| 2 — Training configuration | Exercise library, custom exercises, routines, supersets, split templates and editing                          | Configure a complete training setup                                                                      |
| 3 — Reliable logging       | Set logging, substitutions, previous performance, timers, local checkpoints, offline completion, history      | A workout survives interruption and synchronizes safely                                                  |
| 4 — Adaptive scheduling    | Fixed, Rolling, Adaptive; availability; missed sessions; scoring and explanations; time adaptation; overrides | Missed days yield correct, understandable recommendations                                                |
| 5 — Progress and recovery  | Charts, records, overload suggestions, muscle exposure and SVG map                                            | Analytics derive from real training and respond to corrections                                           |
| 6 — Release refinement     | Export, account deletion, accessibility, performance, update safeguards, deployment preparation               | Release checks pass and limitations are documented                                                       |

Nutrition, social features, wearable integrations, and AI coaching are outside the initial release. No paid AI or Cloud Functions are needed for the approved foundation.

Phase 3 records actual weight/reps, reps, assistance/reps, duration, or distance/duration with optional RPE; it includes timestamp-based rest timers, session snapshots, explicit substitutions, previous completed performance, partial-completion confirmation, and ended-early history. Account-scoped device checkpoints and revision-checked cloud writes preserve interrupted or rejected work. A recovery download is available before explicitly choosing the cloud version.

The initial Phase 4 increment displays the exact next Rolling workout on Today and Train. Starts from that recommendation freeze the split revision, slot, and sequence token. Routine-library starts remain standalone. A scheduled completion counts automatically when all planned sets are performed; partial coverage requires the unchecked-by-default **Count this workout toward my split** choice. Planned coverage includes optional exercises and warmups, and removing logged sets does not shrink the frozen plan. **End early** never counts.

Each split has a revision-aware cursor in `workoutState/current`. A counted completion saves the session, clears the active-workout pointer, and advances that cursor atomically. Checkpoints preserve offline and interrupted work; duplicate or stale advancement cannot consume another slot. Switching active splits preserves their individual cursors, while a split edit starts its new revision at the first training slot. A workout only counts against the active matching split and unchanged next slot. Pre-feature sessions without a sequence token continue to save history without advancement.

Consecutive rest slots after a counted completion reserve full local calendar dates after the completion day. With `N` rest slots, training resumes on the completion's local date plus `N + 1` days; no rest slots impose no delay. Leading rest slots do not block the first workout. An explicit **Train early** confirmation permits starting before the recommended date.

Remaining Phase 4 work includes Fixed and Adaptive modes, availability, scoring and time adaptation, and explicit override events for repeat, skip, swap, and reset. There is no reset interface yet. History pagination beyond the latest 200 changed sessions and correction of terminal history remain later refinements; completed and ended-early sessions are immutable through the client rules. Release the updated client and compatible rules together; no production deployment is implied by these implementation milestones.
